# Installation and native lifecycle dependency

The executable native reconciliation package is delivered under `reconciliation/`, and `src/bundle.rs` embeds and stages it through `devrec af bundle EXECUTABLE DESTINATION`. The builder validates each package with the installed AF parser and generates real digest pins and catalog entries for review. See `docs/af-integration.md` for installation, the counted provider-admission budget and native kernel test. `reconciliation-worker.md` is the instruction source; the installable Worker includes those instructions and its input/output schemas. The Rust production adapter is `src/af.rs`, configured by `schemas/af-integration-v1.json`.

The publication Scenario depends on the separately tracked AF implementation Task `impl-scenario-lifecycle-1`. That change owns fresh implementation-Task allocation, accepted-candidate materialization, signed publication decisions, narrow installed adapter authority, commit/push/PR creation, bounded repairs, exact-head CI/review evidence, actual-merge waiting and owned-resource cleanup. Native schema references are captured in `references/af/`. Runtime pins must be generated from the accepted installed runtime and committed authority. This checkout deliberately does not duplicate the runtime extension, invent action schemas, ship zero/fake pins as executable, or claim the publication Scenario is installed.

Root-coordinator integration must consume the accepted dependency output, build the native bundle against its actual schemas, and test restart reuse of the same Task/PR, changed-head invalidation, closed-without-merge preservation, and refusal of dirty/unowned cleanup before installation. Until that integration, standalone devrec and the delivered native reconciliation package are available. No worker publishes or changes machine accounts.
